# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/): patch — правки описаний и макросов по умолчанию, minor — новые элементы, триггеры, теги, major — смена ключей или формата вывода сборщика.

## [1.3.1] — 2026-09-21

### Исправлено
- Медленно отдаваемая страница ошибки больше не растягивает запрос сверх бюджета. Под Windows PowerShell 5.1 .NET Framework до выдачи кода ответа сам дочитывает тело отказа (до 64 КБ), и ни `Timeout`, ни `ReadWriteTimeout` этого не ограничивают, пока байты идут чаще таймаута: 100 байт по байту в 100 мс держали запрос 10 с при бюджете 1,5 с, страница в 64 КБ могла занять весь проход. Теперь ответ ждётся не дольше бюджета. Если страница ошибки не пришла целиком за бюджет, адрес получает «нет ответа от узла за N мс» (состояние 20, как у медленного тела ответа 200) — кода ответа .NET к этому моменту не отдал. Обычные страницы ошибки — по-прежнему код и текст сервера.

- Когда служба штампов отказывает, элементы «расхождение часов» и «ключ подписи истекает через» больше не становятся неподдерживаемыми. Сборщик отдаёт в них `null`, а числовой элемент его не принимал (`Value "null"`), и триггер «ключ подписи службы истекает» уходил в неизвестное состояние. Теперь не число отбрасывается вторым шагом предобработки: значение приходит только при выданном штампе, как и было описано.

- «Ключ подписи службы истекает» учитывает `{$PKI.ALERT}`, как остальные проблемы адреса. На хосте с выключенными оповещениями, где служба не отвечает никогда, триггер был в состоянии «неизвестно» (нет данных за сутки), теперь он в норме.

**Deploy:** `edo-pki.ps1` на хосты, импорт шаблона (`{$PKI.SCRIPT.MD5}` обновлён).

## [1.3.0] — 2026-09-21

### Исправлено
- В операционных данных 18 проблем адресов (CRL, AIA, OCSP, TSP) вместо причины стояло повторно состояние: `{ITEM.LASTVALUE2}` указывал на второе вхождение элемента состояния в выражении (`max`), а не на элемент причины — он третий. Тест шаблона теперь сверяет номер с позицией элемента причины.
- Отказ после переадресации больше не показывает код предыдущего шага (307) и называет адрес, на котором случился.
- Шаблон снова импортируется: зависимости «ключ подписи службы истекает» ссылались на выражения видов отказа TSP без элемента причины (с 1.2.0), и `configuration.import` отказывал («depends on trigger … which does not exist»). Тест зависимостей это пропускал: соседний тест переписывал выражения разобранного шаблона.

### Изменено
- Операционные данные — фраза по-русски «что произошло. Что делать: …» вместо `CDP_HTTP_FAIL|action=CHECK_ENDPOINT` и `HTTP_BAD (30)`. В неё попадает ответ сервера: код и текст статуса HTTP с началом текстовой страницы ошибки, `PKIStatus`, имена `failInfo` и `statusString` службы штампов, `responseStatus` ответчика OCSP с пояснением. Сетевые отказы названы по сути: «нет ответа от узла за 5000 мс», «имя не найдено в DNS», «сервер закрыл соединение» вместо `INTERNAL_ERROR`.
- Внутренний сбой службы штампов (`52`) — причина `SERVICE_FAILURE` с действием «сообщить в УЦ», а не `UNKNOWN|CHECK_ENDPOINT`.
- Из имён событий адресов убран код состояния: вид отказа уже в имени, подробности — в операционных данных.
- Чтение тела ответа не задаёт таймаут потоку, который его не поддерживает (PowerShell 7): тесты HTTP проходят и вне Windows. Под Windows PowerShell 5.1 поведение прежнее.

**Deploy:** `edo-pki.ps1` на хосты, импорт шаблона (`{$PKI.SCRIPT.MD5}` обновлён). Одного импорта шаблона хватит, чтобы исправить номер причины; фразы вместо кодов появятся по мере раскатки скрипта.

## [1.1.0] — 2026-09-18

### Добавлено
- Проблема «на хосте нечего проверять» (Average): сборщик отработал, но ни сертификатов в источниках, ни адресов в `{$PKI.CRL.URLS}` нет — про подпись не проверяется ничего, и зелёный хост об этом молчал. Элемент `edo.pki.objects`.
- Проблема «сертификат УЦ лежит в хранилище подписи» (Warning, только дашборд) с перечнем таких сертификатов в элементе `edo.pki.ca_certs`: хранилище, УЦ, отпечаток и срок.
- Состояние службы штампов `52 SERVICE_FAILURE` — служба сообщила о своей внутренней ошибке (`failInfo systemFailure`), в отличие от `50`, где она отказала в запросе.

### Изменено
- Сертификат УЦ, лежащий в хранилище из `{$PKI.STORES}`, больше не считается сертификатом хоста: его цепочка в обнаружение не идёт, но сам он остаётся доступен построителю цепочек. Признак — расширение `basicConstraints` с `CA=true`; его отсутствие означает конечный сертификат (RFC 5280).
- Контейнер КриптоПро без сертификата не считается непрочитанным объектом: `csptest -expcert` отвечает `SCARD_E_NO_SUCH_CERTIFICATE` по обоим типам ключа. Таймаут и любой другой код возврата по-прежнему дают неполноту обнаружения.

После обновления «на хосте нечего проверять» поднимется там, где единственным «сертификатом хоста» был сертификат УЦ в хранилище подписи: подпись на таком хосте мониторинг не контролировал и раньше, теперь это видно. Закрывается объявлением адресов в `{$PKI.CRL.URLS}` или отвязкой шаблона.

**Deploy:** `edo-pki.ps1` на хосты, импорт шаблона (`{$PKI.SCRIPT.MD5}` обновлён). Конфиг агента не менялся.
