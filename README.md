# EDO PKI Monitor

> Шаблон Zabbix 7.0 и PowerShell-сборщик: инфраструктура подписи для ЭДО **с самого Windows-хоста** — списки отзыва по сети и в машинном хранилище `CA`, OCSP, сертификаты УЦ по AIA, службы штампов времени и часы хоста.

**Автор:** Konstantin Tyutyunnik / Константин Тютюнник · [itforprof.com](https://itforprof.com)

## Зачем

Работа в Контуре, Такскоме, Госуслугах и ФНС ломается и на проверке сертификата: список отзыва не скачивается, OCSP не отвечает, служба штампов недоступна. Пользователь видит зависание КриптоПро и браузера или отказ подписи, а [EDO Monitor](https://github.com/IT-for-Prof/zabbix-edo-monitor), проверяющий доступность самих сервисов, этого не показывает. Этот пакет отвечает на другой вопрос — работает ли подпись на этой машине.

Адреса CRL, OCSP и сертификатов УЦ пакет берёт из действующих сертификатов самого хоста, поэтому новый сертификат или УЦ попадает под мониторинг без правки шаблона.

## Что проверяется

Сборщик `edo-pki.ps1` раз в `{$PKI.INTERVAL}` делает один проход и отдаёт JSON; правила обнаружения заводят по нему объекты.

| Объект | Откуда | Проверка |
|---|---|---|
| Адрес CRL | CDP всех звеньев цепочек, `{$PKI.CRL.URLS}` | начало (16 КБ) и хвост (4 КБ) файла: это CRL, размер по DER равен размеру на сервере, издатель и AKI совпадают с сертификатом, `nextUpdate` не в прошлом |
| Сертификат УЦ | AIA `caIssuers` | отдан сертификат, его субъект — издатель звена, SKI — AKI звена |
| Ответчик OCSP и статус сертификата | AIA `ocsp` действующих сертификатов | запрос с `CertID` SHA-1: `good`, `revoked`, `unknown` |
| Локальный список отзыва | УЦ звеньев с http-CDP и издатели списков из `{$PKI.CRL.URLS}` | действующий CRL в машинном хранилище `CA`, сопоставление по AKI |
| Служба штампов | `{$PKI.TSP.URLS}` | штамп на хэш ГОСТ Р 34.11-2012: `granted`, эхо `nonce` и хэша, срок ключа подписи (PKUP) |
| Часы хоста | службы, выдавшие штамп | наименьшее по модулю расхождение с временем штампа |

Источники сертификатов — машинные хранилища Windows (`{$PKI.STORES}`) и контейнеры КриптоПро, видимые LocalSystem (`{$PKI.CONTAINERS}`). Сертификат удостоверяющего центра, лежащий в хранилище подписи, сертификатом хоста не считается: его цепочка не проверяется, а сам он остаётся доступен построителю цепочек и попадает в проблему «сертификат УЦ лежит в хранилище подписи». Проверяются только действующие сертификаты: у истёкшего сертификата единственного УЦ его адреса пропадают из обнаружения. Редиректы HTTP выполняются вручную, до 5 переходов и только на `http://` (у ФНС CRL отдаётся после двух ответов 307). Подписи CRL, OCSP и штампов не проверяются.

Службы штампов по умолчанию — из официальных источников, выдавали штамп на ГОСТ 16.09.2026:

| Служба | Источник адреса |
|---|---|
| `http://tsp2012.taxcom.ru/tsp/tsp.srf` | taxcom.ru, «Сертификаты, отзыв ЭП» |
| `http://pki.skbkontur.ru/tsp2012/tsp.srf` | kontur.ru/qa/15922 (редирект на службу Сертума) |
| `http://pki.tax.gov.ru/tsp/tsp.srf` | nalog.gov.ru, «Ресурсы Удостоверяющего центра ФНС России» |

## На что реагирует

| Проблема | Серьёзность | Когда |
|---|---|---|
| `EDO PKI сертификат <id> (<УЦ>, до <дата>): отозван` | High | OCSP вернул `revoked` |
| `EDO PKI локальный CRL <УЦ>: нет действующего списка` | High | в хранилище `CA` нет списка по AKI или он истёк |
| `EDO PKI CRL <УЦ>: узел недоступен <адрес>` (и AIA, OCSP, TSP) | Average | все проверки за `{$PKI.FAIL.PERIOD}` — сетевой отказ, состояния 10–29 |
| `EDO PKI CRL <УЦ>: сервер отвечает ошибкой <адрес>` (и AIA, OCSP, TSP) | Average | все проверки — 30–39 |
| `EDO PKI CRL <УЦ>: не тот список <адрес>`, `AIA: не тот сертификат`, `OCSP: ответ не OCSP`, `TSP: ответ не штамп` | Average | все проверки — 40–49 |
| `EDO PKI OCSP: ответчик отказывает <адрес>`, `TSP: служба не выдаёт штамп` | Average | все проверки — 50–89 |
| `EDO PKI CRL <УЦ>: отказы разного вида <адрес>` (и AIA, OCSP, TSP) | Average | все проверки — отказ (10–89), но разного вида |
| `EDO PKI сертификат <id>: статус неизвестен` | Average | OCSP вернул `unknown` все проверки за период |
| `EDO PKI: часы хоста расходятся со службами штампов` | Average | наименьшее расхождение больше `{$PKI.CLOCK.MAX}` с; закрывается и когда штампов нет дольше `{$PKI.NODATA}` |
| `EDO PKI: обнаружение неполное` | Average | источник, контейнер или адрес не прочитан |
| `EDO PKI: проход не уложился в срок` | Average | проход не закончился за 90 с |
| `EDO PKI: сборщик не работает` | Average, одна на хост | нет результата дольше `{$PKI.NODATA}` или сборщик сообщает ошибку |
| `EDO PKI: версия скрипта сборщика не совпадает` | Average | MD5 `edo-pki.ps1` ≠ `{$PKI.SCRIPT.MD5}` |
| `EDO PKI: на хосте нечего проверять` | Average | сертификатов в источниках нет и `{$PKI.CRL.URLS}` пуст, при полном обнаружении |
| `EDO PKI: сертификат УЦ лежит в хранилище подписи` | Warning | в `{$PKI.STORES}` найден сертификат УЦ |
| `EDO PKI локальный CRL <УЦ>: истекает` | Warning, только дашборд | осталось меньше `{$PKI.LOCAL.WARN.PCT}`% периода списка |
| `EDO PKI TSP: ключ подписи службы истекает` | Warning, только дашборд | срок ключа за сутки меньше `{$PKI.TSP.KEY.DAYS}` дней |

**Проблема адреса — по виду отказа.** У адреса на каждый вид (сеть, ответ сервера, содержимое, служба) свой триггер и ещё один — «отказы разного вида» (тег `failure`). Они взаимоисключающие: у адреса открыта не больше одной проблемы. Узел, который отвечает то таймаутом, то отказом соединения, — одна проблема «узел недоступен»; то таймаутом, то HTTP 500 — «отказы разного вида». Смена вида (например, HTTP 500 → не тот ключ) проходит через один период «отказы разного вида»: прежняя проблема закрывается и новая открывается в той же оценке, без промежутка. Проверка, которой не было (90), проблему не закрывает. В имени события код на момент открытия, текущий — в операционных данных. Поведение проверено на сервере Zabbix 7.0.30.

Все проблемы объектов зависят от «сборщик не работает», а он — от стандартных триггеров доступности агента из «Windows by Zabbix agent active»: когда агент или сборщик молчат, приходит одна проблема. Сбой одного УЦ даёт по проблеме на каждый его адрес на каждом хосте — тревога отражает сеть конкретной машины. Свести адреса одного узла зависимостями нельзя: Zabbix 7.0.30 не переносит на обнаруженные триггеры зависимость от прототипа другого правила обнаружения (проверено), а внутри одного правила переносит — так «ключ подписи службы истекает» зависит от всех видов отказа той же службы.

Теги: на шаблоне `class: service`, `target: edo-pki`, `vendor: itforprof`; на элементах `component`, у объектов `url`, `ca` или `certificate`; на триггерах `scope`. В именах и тегах нет данных владельцев сертификатов: сертификат обозначен первыми 8 символами SHA-256 от отпечатка, издателем и датой окончания.

## Требования

- Встроенный Windows PowerShell 5.1; проверено на Windows Server 2022 и 2025.
- Zabbix agent 2 версии 7.0, активные проверки: агент новее сервера 7.0 несовместим (документация Zabbix 7.0, Compatibility).
- «Windows by Zabbix agent active» на том же хосте — от его триггеров зависит «сборщик не работает».
- КриптоПро CSP с `csptest` — только для источника «контейнеры».
- Исходящий HTTP (порт 80) к узлам УЦ для `powershell.exe`. На хостах с исходящим `Block` — адресные правила. Узлы, для которых на хосте с закрытым исходящим трафиком 16.09.2026 понадобились правила (полный набор узлов конкретного хоста — адреса в его обнаружении):

| Узлы | IP на 16.09.2026 | Что за ними |
|---|---|---|
| `pki.tax.gov.ru`, `uc.nalog.ru` | 213.24.64.95 | CRL, caIssuers, OCSP и TSP ФНС |
| `cdp.tax.gov.ru` | 213.24.64.113 | CRL и caIssuers ФНС |
| `company.rt.ru` | 213.59.197.65 | CRL Минцифры |
| `rostelecom.ru` | 87.226.162.216 | CRL Минцифры |
| `ca.vtb.ru`, `pki1.vtb.ru` | 195.242.82.0/24, 195.242.83.0/24 (RIPE VTB-BANK-NET) | CRL, caIssuers, OCSP ВТБ |

  IP-правила не следуют за сменой адресов в DNS: при появлении состояния 23 FIREWALL_DENIED сверить адрес узла заново.
- Машинное хранилище `CA` Windows само списками УЦ ЭДО не заполняет (на хосте без установки списков в `CA` один список на 437 байт): локальная проверка нужна там, где списки устанавливаются отдельно (`certmgr -inst -store mCA -crl`), иначе `{$PKI.LOCAL}` = 0.

## Установка

На каждом наблюдаемом хосте, от администратора:

```powershell
$agent = 'C:\Program Files\Zabbix Agent 2'
$scripts = Join-Path $agent 'scripts'
New-Item -ItemType Directory -Force $scripts | Out-Null
# Запись — только Administrators и SYSTEM: скрипт исполняется от LocalSystem.
icacls $scripts /inheritance:r /grant:r '*S-1-5-32-544:(OI)(CI)F' '*S-1-5-18:(OI)(CI)F' '*S-1-5-32-545:(OI)(CI)RX'
Copy-Item .\agent\edo-pki.ps1 (Join-Path $scripts 'edo-pki.ps1')
Copy-Item .\agent\edo-pki-monitor.conf (Join-Path $agent 'zabbix_agent2.d\edo-pki-monitor.conf')
Restart-Service 'Zabbix Agent 2'
```

Скрипт лежит по пути `C:\Program Files\Zabbix Agent 2\scripts\edo-pki.ps1` — этот же путь записан в `edo-pki-monitor.conf` и в элементе `vfs.file.md5sum` шаблона. Файлы берутся из git-клона с CRLF (так их кладёт `.gitattributes`), иначе MD5 не совпадёт с `{$PKI.SCRIPT.MD5}`.

**Подключение — перезапуском службы, не `zabbix_agent2 -R userparameter_reload`**: агент 7.0.12 упал на перезагрузке параметров, пока шла проверка изменяемого параметра.

Кэш сертификатов контейнеров — `%ProgramData%\zabbix-edo-pki-monitor\`, доступ только SYSTEM и Administrators (в кэше сертификаты с ФИО). Каталог (или соединение, файл) с чужим владельцем или лишними правами сборщик не трогает: переименовывает в `zabbix-edo-pki-monitor.untrusted-<guid>` и создаёт новый с нужными правами. Такой переименованный объект — повод разобраться, кто его создал, и удалить.

Проверка на хосте до привязки шаблона — от SYSTEM (например, разовой задачей планировщика), иначе контейнеры и хранилища видны не так, как агенту:

```powershell
& 'C:\Program Files\Zabbix Agent 2\zabbix_agent2.exe' -c 'C:\Program Files\Zabbix Agent 2\zabbix_agent2.conf' -t 'edo.pki["1","1","My","1","","http://tsp2012.taxcom.ru/tsp/tsp.srf"]'
```

В Zabbix:

1. Импортировать `template/edo-pki-monitor-by-zabbix-agent-active.yaml`: «Create new» и «Update existing» включены, «Delete missing» выключен.
2. Привязать шаблон к хосту вместе с «Windows by Zabbix agent active».
3. Первый проход — через `{$PKI.INTERVAL}`. «Execute now» для активных элементов Zabbix не разрешает. Чтобы не ждать: временный макрос хоста `{$PKI.INTERVAL}` = `1m`, для хостов за прокси — «Refresh configuration» прокси, после первых данных макрос убрать.

Новая версия скрипта: раскатать `edo-pki.ps1`, затем записать его MD5 в `{$PKI.SCRIPT.MD5}` на шаблоне (`(Get-FileHash edo-pki.ps1 -Algorithm MD5).Hash.ToLower()`).

## Управление

| Задача | Действие в Zabbix |
|---|---|
| Адрес постоянно мёртв (внутреннее имя УЦ) | на шаблоне `{$PKI.ALERT:regex:"^http://имя/"}` = `0`: значения собираются, проблем нет |
| Хост без выхода в интернет | на хосте `{$PKI.NETWORK}` = `0`: сетевые объекты уходят, локальные списки проверяются |
| Списки в `CA` на хосте не устанавливаются | на хосте `{$PKI.LOCAL}` = `0` |
| На хосте нет КриптоПро | на хосте `{$PKI.CONTAINERS}` = `0` |
| Список нужного УЦ без сертификата на хосте | `{$PKI.CRL.URLS}` через запятую |
| Другая служба штампов | `{$PKI.TSP.URLS}` через запятую; пусто — штампы и часы не проверяются |

Адреса в макросах — только `http://` из `A-Z a-z 0-9 . _ / -` с необязательным портом: `?`, `&`, `%`, кавычки и пробелы не проходят проверку сборщика (agent2 часть из них не пропускает в параметры ключа, cmd.exe раскрывает `%VAR%`). Неверный макрос — проблема «сборщик не работает» с текстом «invalid argument».

## Состояния и что делать

Состояние адреса CRL, AIA, OCSP или службы штампов. Проблема — все проверки за `{$PKI.FAIL.PERIOD}` в диапазоне 10–89. Подробности — поле `error` объекта в истории «результат сборщика».

| Код | Имя | Что значит | Что делать |
|---|---|---|---|
| 0 | OK | ответ получен и верен | — |
| 1 | CONTENT_UNCHECKED | сервер игнорирует запрос части файла, содержимое не проверено | проблемы нет; наблюдать |
| 10 | DNS_FAIL | имя не разрешается | внутреннее имя УЦ — исключить адрес; иначе DNS хоста |
| 20 | TIMEOUT | нет ответа за 5 с | узел УЦ не отвечает; сравнить с другими хостами |
| 22 | REFUSED | соединение отвергнуто | узел не слушает порт |
| 23 | FIREWALL_DENIED | локальный фаервол не пускает `powershell.exe` | правило исходящего фаервола для адреса узла |
| 24 | NETWORK_FAIL | прочая сетевая ошибка | поле `error` |
| 30 | HTTP_BAD | ответ не 200/206, больше 5 редиректов или редирект не на `http://` | сбой на стороне УЦ |
| 40 | BAD_FORMAT | по адресу не CRL, не сертификат, не ответ OCSP или штампа | заглушка вместо файла |
| 41 | SIZE_MISMATCH | размер на сервере не равен размеру по DER | файл обрезан на сервере |
| 42 | ISSUER_MISMATCH | издатель списка или субъект сертификата УЦ не тот | по адресу другой УЦ |
| 43 | KEY_MISMATCH | AKI списка или SKI сертификата не тот | УЦ сменил ключ при прежнем адресе |
| 44 | LIST_EXPIRED | сервер отдаёт просроченный список | УЦ перестал выпускать список |
| 50 | SERVICE_REFUSED | OCSP не `successful` или служба штампов отказала | сбой службы или не принимает ГОСТ-хэш |
| 51 | ECHO_MISMATCH | ответ не про запрошенный серийный номер, `nonce` или хэш | ответ из кэша или на другой запрос |
| 52 | SERVICE_FAILURE | служба штампов сообщила о своей внутренней ошибке (`failInfo systemFailure`) | сбой на стороне УЦ; одиночные отказы поглощает `{$PKI.FAIL.PERIOD}` |
| 90 | NOT_CHECKED | срок прохода вышел: объект не проверен или запрос оборван сроком прохода | проблема «проход не уложился» |

Статус сертификата по OCSP: -1 NOT_CHECKED (ответчик не ответил, издателя нет в цепочке — это ещё и неполное обнаружение, сеть выключена), 0 GOOD, 1 REVOKED, 2 UNKNOWN. Ответчик, не ответивший по сети, в этом проходе больше не спрашивается: остальные его сертификаты получают -1.

Непроверенный объект (-1, 90) проблему не закрывает: проблемы адресов закрываются при состоянии меньше 10 или исключении адреса, «отозван» и «статус неизвестен» — при другом полученном статусе. Локальный список: 0 VALID, 1 MISSING, 2 EXPIRED.

## Границы

- Срок действия самих сертификатов пользователей и УЦ не проверяется; истёкшие сертификаты не порождают проверок.
- Подписи CRL, OCSP и штампов не проверяются: целостность подтверждается структурой, совпадением `nonce`, хэша, издателя и AKI.
- Звенья УЦ без адреса OCSP по OCSP не проверяются.
- Сертификаты в файлах `.cer`, пользовательские хранилища и контейнеры, невидимые LocalSystem, `ldap`-адреса — вне задачи.
- Пакет ничего не исправляет: не скачивает и не устанавливает списки, не правит фаервол.

## Подводные камни

- **Значение элемента длиннее 65 535 символов сервер режет молча.** Сборщик ограничивает вывод 60 000 символами; больше — ошибка «output too large» без списков, объекты обнаружения сохраняются.
- **`zabbix_agent2 -t` не соблюдает таймаут.** Скрипт со сном 20 с при `Timeout=5` отработал до конца; таймаут элемента проверяется только через сервер. `Timeout` больше 30 в конфиге агента запрещён; таймаут элемента 60 и 120 с для активной проверки работает, по таймауту агент убивает скрипт.
- **`userparameter_reload` уронил агент 7.0.12** при идущей проверке изменяемого параметра. Подключать и снимать параметры — перезапуском службы.
- **ГОСТ-токены штампов без КриптоПро.** `SignedCms.Decode` .NET без КриптоПро отвергает ГОСТ-алгоритмы («Unknown cryptographic algorithm»), поэтому ответ службы разбирается как DER — работает и на хосте без КриптоПро.
- **У ФНС штампы подписывают разные ключи**: срок ключа между проходами — 23.12.2028 или 28.01.2029. Warning по сроку ключа считает минимум за сутки.
- **В сертификатах служб штампов Такскома и Контура в CN — ФИО сотрудника.** Сборщик субъекты сертификатов не выводит.
- **`csptest -enum_cont` выводит имена в cp866**: в других кодировках часть имён с кириллицей не открывается.
- **Контейнер без сертификата — норма.** Контейнер с одними ключами `csptest -expcert` не отдаёт (`SCARD_E_NO_SUCH_CERTIFICATE`, на живом хосте 6 из 10 контейнеров), и неполнотой обнаружения это не считается. Неполнота остаётся за таймаутом и любым другим кодом возврата.
- **Сбой перечня контейнеров не очищает кэш.** Таймаут или ненулевой код `csptest -enum_cont` — источник `containers` с состоянием 1, сертификаты из кэша остаются в проверке. Код выхода на хосте без контейнеров не замерялся: если там он ненулевой, на таком хосте нужно `{$PKI.CONTAINERS}` = 0.
- **`HttpWebRequest.Timeout` не ограничивает разрешение имени** (по документации до 15 с): имя разрешается заранее в пределах бюджета запроса.
- **Имя контейнера пишет пользователь.** Имя с обратным слэшем или управляющим символом отвергается; остальные передаются `csptest` по правилам `CommandLineToArgvW` — имя, начинающееся с кавычки, не подставит свои аргументы процессу SYSTEM.
- **Проблема объекта, пропавшего из обнаружения, остаётся открытой.** Zabbix 7.0.30 выключает элементы и триггер сразу (проверено 17.09.2026: `status` = 1, значение триггера осталось «проблема»), а удаляет через 7 дней. Так бывает после смены `{$PKI.CRL.URLS}`, `{$PKI.TSP.URLS}`, `{$PKI.NETWORK}` или ухода сертификата УЦ: такую проблему закрыть вручную (`manual_close` включён).
- **Период отказов — макрос целиком** (`#2`): Zabbix 7.0 не принимает `#{$MACRO}` в параметре функции.

## Разработка

Тесты — Pester 6.2.0 и `powershell-yaml` 0.4.12 (машинная установка), только под Windows PowerShell 5.1, от администратора (тесты кэша ставят владельца каталога):

```powershell
powershell.exe -NoProfile -Command "Invoke-Pester -Path tests -CI"
```

- `tests/Der.Tests.ps1` — разбор CRL, адресов сертификатов, OCSP и штампов, в том числе ГОСТ-токена.
- `tests/Http.Tests.ps1` — редиректы, части файла, бюджет и классы отказов на локальном сервере.
- `tests/Discovery.Tests.ps1` — адреса и набор УЦ, хранилища, контейнеры на фейковом `csptest`, кэш и его права.
- `tests/Collector.Tests.ps1` — проход целиком на тестовом УЦ и контракт вывода, запуск как у agent2.
- `tests/Template.Tests.ps1` — согласованность шаблона, сборщика, конфига агента и этого README.
